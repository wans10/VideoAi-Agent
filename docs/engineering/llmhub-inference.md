# LLM Hub inference routes

`LLMHUB_API_KEY` is a server-only model inference key, separate from `LLMHUB_PAY_*` merchant credentials. Never put it in source, a build argument, or `NEXT_PUBLIC_*` configuration. The directory was checked with `GET https://api.llmhub.com.cn/v1/models`; model IDs below are exact directory IDs. Catalog presence confirms an endpoint type, not a successful paid generation or every optional parameter.

The image executor selects Google Vertex for Nano Banana and BytePlus for Seedream 5.0 Lite when those direct providers are configured, then LLM Hub when direct is unavailable. GPT Image has no direct provider in this repository and uses LLM Hub. The executor checks the selected provider's credentials before reserving the wallet charge. Explicit direct provider rejections before a response ID may switch to LLM Hub with the existing job and charge; uncertain outcomes and accepted responses retain their own failure or recovery path. Gemini references use inline data with a 7 MB per-file and 30 MB per-request transport cap; Gemini inline outputs are uploaded to owned storage before completion.

## GPT Image 2.5 verified protocol (2026-10-08)

Flare and Sunburst use JSON `/v1/images/generations` and multipart `/v1/images/edits`. They reject `response_format`; successful outputs are `data[].b64_json`. The adapter persists decoded PNG/JPEG originals under the account-owned `renders/images` prefix before the normal thumbnail/job completion path. It preserves the provider request ID before parsing/persisting outputs and never repeats the paid POST on storage errors or uncertain failures. Returned image count, encoding, format and dimensions must match the request before completion. Every PNG/JPEG is fully decoded with Sharp before any batch upload. Upload failures roll back only newly allocated keys from this attempt, tracked before PUT; incomplete deletes expose exact remaining keys in persisted failure detail. Cleanup cannot be guaranteed during a storage outage or abrupt process termination. Legacy GPT Image 2 and Seedream URL handling is unchanged.

Output controls expose PNG/JPEG only (WebP remains an accepted reference input). The valid landscape choice is 1920×1088; the historical 1920×1080 vendor price tier remains the existing estimated billing basis, not a verified LLM Hub invoice. Edit Auto selects a provider-valid size from the source dimensions (or 1024×1024 fallback), uses it for the quote and sends that explicit size, avoiding provider-selected output dimensions. Historical jobs/pricing facts are not migrated.

The live adapter canaries passed both models in t2i at 1920×1088 and i2i at explicit 1024×768 with local persistence substitution. The prior bounded protocol audit accepted 4 outputs, 16 references plus mask, custom JPEG and quality tiers. Sunburst xhigh transparency and max 4K requests hit upstream 504 at about 120 seconds; these high-load combinations remain operationally unverified. Raising the application timeout alone cannot fix a shorter upstream gateway limit. No asynchronous or server-recovery endpoint has been certified for these models, and the implementation does not silently downgrade quality or repeat a timed-out request. Supplier invoice rates and reference surcharges still require actual account billing verification.

See `llmhub-gpt-image-audit-2026-10-08.md` for the pre-fix evidence and `llmhub-gpt-image-implementation-2026-10-08.json` for sanitized live adapter validation. Configure the existing server-only `LLMHUB_API_KEY`; no new production credential or build-time secret is required.

## Existing video engines

If the LLM Hub inference key is absent, Fal-compatible video modes retain their Fal route.

Set `LLMHUB_INFERENCE_ROUTING_ENABLED=true` and configure `LLMHUB_API_KEY`. Configured Alibaba Model Studio, BytePlus ModelArk, and Google Vertex Veo direct routes take precedence. LLM Hub is selected when the applicable direct route is unavailable and the request matches its verified shape. It also receives a safely rejected pre-acceptance submission from Alibaba or Google Vertex Veo, and explicit BytePlus 401/403/404/429 rejections before any task ID. The LLM Hub route applies only to `t2v` and single-image `i2v` for `seedance-2-0`, `seedance-2-0-fast`, `seedance-2-0-mini`, `seedance-2-5`, `wan-3`, and `wan-3-prime`. All three Veo 3.1 variants use LLM Hub only for the verified 8-second, 720p, 16:9 text-to-video setting. Their image modes and other settings keep their previous route. Multipart Veo submissions returned `channel base URL is invalid` on 2026-09-29; the corrected JSON path completed on all three variants. The directory also advertises `/v1beta/models/veo-3.1-lite-generate-001:predictLongRunning` for Veo Lite, but a 4-second 720p text canary using Vertex-style `instances` returned `contents is required`; using `contents` then returned `model_price_error` because the channel's `u("seconds")` pricing input was null, including when `seconds` and `resolution` were sent at the top level. None of these Gemini-endpoint requests returned a task ID. The Gemini-style endpoint remains unverified. The exact model IDs live in `frontend/src/server/video-providers/llmhub/model-map.ts`. The special `seedance-2-0-fast-byteplus` route still uses BytePlus because its request and pricing lifecycle bypass the general video router. Other video modes, explicit audio-off requests, and requests with additional references or advanced controls keep their existing provider route; `/v1/videos` does not document the required reference-video, first/last-frame, or extension fields.

On 2026-09-29 and 2026-09-30, 8-second, 720p JSON requests to `POST /v1/videos` completed for Veo 3.1, Fast, and Lite. All three MP4 files were downloadable; their movie headers show 8 seconds, 1280x720 video, and audio tracks. A user-created Veo Lite task also returned HTTP 200 from the same content endpoint. The Lite task initially returned HTTP 410 `artifact_gone` before a later retry returned HTTP 200 `video/mp4`; the poller leaves temporary content failures active for another attempt. Veo single-image mode and other text settings remain unverified through the JSON path.

Submission uses `POST /v1/videos` multipart fields `model`, `prompt`, `seconds`, and optional `input_reference`. For Seedance and Wan, a tested image reference is a URL in both `input_reference` and `metadata.content`; uploading a file received a 400 rejection. Seedance resolution is carried in `metadata.resolution`: `size=480p` and `size=854x480` both produced 720p for Mini, while `metadata.resolution=480p` produced a 480p-class file. Wan 480p/16:9 accepts `size=832x480` and emits 854x480; `854x480` was rejected. These are tested adapter observations, not a general guarantee for every resolution and aspect ratio. Seedance image-to-video output follows the source image ratio, so the poller checks its resolution and records the actual output ratio. Polling uses `GET /v1/videos/{task_id}` and downloads the MP4 stream from `GET /v1/videos/{task_id}/content` into owned storage. The poller verifies duration and dimensions, checks an explicitly selected audio option, and records the actual audio presence when no audio option was selected; a mismatch against an explicit choice is refunded. Both the per-job refresh and `/api/cron/llmhub-video-poll` call the same poll owner. The poll lease is ten minutes to cover the bounded MP4 transfer. Configure an authenticated one-minute scheduler for the cron route on hosts without Vercel cron. Confirm it runs before enabling public routing. The poller leaves an aged ambiguous task for manual review and persists a wallet refund before marking a definite provider failure.

The published LLM Hub documentation gives generic Sora-compatible video shapes; it does not certify per-model durations, resolutions, or all image input variants. On 2026-09-29, authorized canaries reached completed MP4 output for text and URL-backed single-image modes on all six Seedance/Wan engines. The first frame of corrected image-mode outputs retained the supplied image. The three Veo variants rejected multipart submission before task creation with the same channel base URL error; later JSON submissions completed and yielded downloadable MP4 files for all three. These canaries cover selected 480p or default settings and native audio; other resolutions, ratios, audio-off, and advanced modes remain unverified. The account-balance endpoint did not accept the inference token, so actual account debit could not be read; the 25 accepted exploratory tasks were estimated at about ¥105 from public pricing using 1 USD = 8 CNY, within the authorized ¥200 cap. Existing vendor cost facts were calibrated to previous providers; customer quotes remain unchanged, and vendor cost or margin reports must not be trusted until actual LLM Hub fees are entered into the pricing source and validated.
