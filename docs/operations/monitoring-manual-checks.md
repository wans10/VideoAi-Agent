# 无法自动监控、必须人工查看的服务商余额与配额

本仓库没有（也不应保存）各服务商的管理员级 API 凭据，生产环境无法在此查询余额。以下项目必须在各家控制台人工查看，并在服务商后台设置自己的余额预警（短信/邮件）。自动监控只能在**已经发生**账号/余额类错误后告警（见 `monitoring.md`）。

下表的建议阈值是起步值，请按实际日消耗调整（目标：余额至少能支撑 3 天消耗）。

| 服务商 | 控制台 | 查看内容 | 建议人工阈值 / 频率 |
| --- | --- | --- | --- |
| 阿里云百炼（Alibaba Model Studio，Kling 3 系列 / MiniMax-H3 首选通道） | 阿里云控制台 → 百炼 → 模型用量 / 费用与成本 → 账户余额；API-KEY 管理 | 账户余额（欠费会返回 Arrearage）、各模型限流/免费额度、API Key 是否过期 | 余额 < 3 天消耗或 < ¥1,000 时充值；每周一检查；开启欠费提醒 |
| 火山引擎方舟（Volcengine Ark，Seedance 等） | 火山引擎控制台 → 火山方舟 → 开通管理 / 用量统计；费用中心 → 账户余额 | 余额与欠费（AccountOverdue）、模型 TPM/并发配额（SetLimitExceeded、QuotaExceeded）、推理接入点是否有效 | 余额 < 3 天消耗时充值；每周检查配额；开启费用中心预警 |
| 可灵 Kling 官方 API | 可灵 AI 开放平台 → 控制台 → 资源包 / 账单 | 资源包剩余量与到期日（余额不足 / 资源包耗尽会导致 1102 类错误）、并发上限 | 资源包剩余 < 20% 或到期前 14 天补购；每周检查 |
| MiniMax 官方开放平台（H3、Hailuo、语音） | MiniMax 开放平台 → 账户管理 → 余额 / 用量 | 余额（insufficient balance，1008）、速率限制与语音额度 | 余额 < 3 天消耗时充值；每周检查 |
| OpenAI（Milo 助手、图片） | platform.openai.com → Settings → Billing（Usage limits） | 余额/预付额度、月度上限（billing_hard_limit_reached、insufficient_quota） | 余额 < US$50 或低于 3 天消耗时充值；设置 Usage limit 与邮件预警 |
| Google Vertex AI（Google Cloud） | Google Cloud Console → Billing → Budgets & alerts；IAM 配额页 | 预算与付款方式、Vertex 区域配额 | 建立 50%/90%/100% 预算提醒；每月检查 |
| 聚合易支付 / LLM Hub Pay | 商户后台 | 商户状态、可用通道、结算额、回调失败记录 | 每天对账；回调有失败记录时立即处理 |
| 阿里云短信 | 阿里云控制台 → 短信服务 → 概览 | 余额/套餐包余量、签名与模板状态 | 余量 < 3 天发送量时购买；每周检查 |
| 阿里云 / AWS 主机与带宽 | 阿里云 ECS/轻量服务器控制台；AWS Billing | 到期时间、欠费、磁盘与流量 | 到期前 30 天续费；磁盘 > 80% 处理 |
| 域名与证书 | 域名注册商 / 1Panel 证书管理 | `keyvo.cn` 域名到期时间（自动 TLS 监控只看证书，不看域名注册到期） | 到期前 60 天续费 |

建议建立一份共享表格，记录每个服务商的最近检查日期、余额和负责人。
